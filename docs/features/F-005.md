# F-005 — Open Document (abrir documento)

> **Estado da evidência.** Tudo nesta spec é da versão-alvo **v24.03.10017**:
> estática de `Document.dll` (SHA-256 `DA91E28574C877D392D3E6BEF9CCBB7C4DCF3117EBD03655DE89834FC8FA9E21`,
> 4.421.040 bytes) e comportamento `CAP-20261121-01` (sessão de 2026-11-21 na GUI real).
> Não há evidência herdada de outra versão nesta funcionalidade.

## 1. Resumo

`File > Open...` abre **um único** diálogo nativo de arquivo cujo filtro enumera todas as
extensões suportadas; não existem comandos separados por formato. O arquivo escolhido é
despachado por **MIME** (`DocumentIO::FileDispatcher::OpenFile`, `0x1802160B0`) para o handler
registrado, que cria o `ArtDoc::Document`, conta as páginas do `GODocument` e devolve o
documento ao viewport **sem diálogo intermediário**.

## 2. Entrada

- **Tipo de documento:** qualquer arquivo cujo MIME tenha handler registrado no
  `FileDispatcher`. O filtro da UI enumera `*.pdf; *.pdpdla; *.ap; *.art`
  (`CAP-20261121-01`, diálogo `Open File`); apenas PDF foi exercitado na captura.
- **Seleção:** nenhuma. A abertura não consome a seleção do documento corrente.
- **Camadas:** todas as camadas do arquivo são lidas na abertura; nenhuma pré-seleção.
  Observado em `test_vector.pdf`: 1 camada, `Unlayered Art`.
- **Pré-condições (comprovadas no binário):**
  1. `boost::filesystem::detail::status(path)` retorna `>= 2` (o arquivo existe e é
     acessível). Caso contrário, exceção de abertura código `0` (`0x1802160B0` passo 1;
     `0x18008F590` passo 2; `0x1800A0EC0`).
  2. O MIME devolvido por `ExtraBoostFilesystem::MimeType::GetMimeType(path)` precisa ter
     entrada no `std::map` do dispatcher. Sem entrada → exceção código `7`
     (`0x1802160B0` passo 3–4).
  3. O documento precisa produzir pelo menos uma página (`0x180093D60`), senão exceção
     código `2`.

## 3. UI

### Caminho

`File > Open...` — observado literalmente em `CAP-20261121-01` (passos 3–5, capturas
`shot-02-app-open.png` e `shot-03-file-menu.png`). **Não existe menu `Documents`** na v24;
a barra de menus literal é `File  Edit  Object  Select  Prepress  View  Window  Help`.

Item literal no popup de `File`, na ordem observada: `New`, `New Report Template...`,
**`Open...`**, `Open Recent`, `Close`, `Close All`, `Save`, `Save As...`, `Export To`,
`Convert To PDF+`, `Convert To Report Template...`, `Convert To Variable Data Template...`,
`Action Lists`, `Launch Workflow...`, `Insert Content From PDF...`, `Place File...`,
`Place Image Inside...`, `Pages`, `Page Boxes Setup...`, `Document Setup...`, `Print...`,
`Exit`.

- **Atalho:** **não medido**. A captura abriu por clique em `File > Open...`; nenhum
  acelerador (`Ctrl+O` inclusive) foi exercitado nem lido no binário. Ver §8.

## 4. Regras

R1. **Um único comando, um único filtro.** `Open...` não ramifica por formato na UI: a
   lista de extensões aceitas é a do filtro `All supported documents (*.pdf; *.pdpdla;
   *.ap; *.art)`. A distinção entre formatos acontece depois, no despacho por MIME.

R2. **Despacho por MIME** — `DocumentIO::FileDispatcher::OpenFile` (`0x1802160B0`,
   `unique_ptr<ArtDoc::Document> OpenFile(FileDispatcher*, path const&, ReadOptions const&)`):
   1. `boost::filesystem::detail::status(path, ec)`; se o resultado for `< 2`, constrói
      `ArtDoc::DocumentOpenException(path, 0)` e lança via `_CxxThrowException`.
   2. `ExtraBoostFilesystem::MimeType::GetMimeType(path)` obtém o MIME (derivado de
      conteúdo/extensão pela camada ExtraBoostFilesystem).
   3. Procura o MIME num `std::map<std::string_view, std::unique_ptr<OpenFileHandler>>`
      (busca binária com `memcmp` sobre a chave `string_view`).
   4. Chave ausente → `DocumentOpenException(path, 7)` e lança.
   5. `AddToOpeningFiles(path)` (`0x180215D50`); invoca o handler pelo **slot 1** da vtable
      — `(*(vtable + 8))(handler, path, options, out)`; `RemoveFromOpeningFiles(path)`
      (`0x180216380`); devolve o `unique_ptr<Document>`.
   - **Não há sniffing de bytes de formato no `Document.dll`**: a decisão é
     MIME → handler registrado.

R3. **Registro do handler** — `DocumentIO::FileDispatcher::RegisterFileHandler`
   (`0x180216270`, `void RegisterFileHandler(FileDispatcher*, string_view const& mime,
   unique_ptr<OpenFileHandler>)`) insere/atualiza a entrada no mapa do dispatcher. Chave
   duplicada é ignorada (o handler recebido é destruído; inferência marcada na evidência).
   O registro dos handlers ocorre na inicialização do DocumentLayer
   (`0x1800A1230`, log `File handlers registered (6/7)`, dois call sites em `0x1800A1DB6`
   e `0x1800A1E20`) sob a chave `"application/illustrator"` (string @`0x1802EAC60`).

R4. **Handler de abertura** — `0x1800A2E40` (slot 1 da vtable `OpenDocumentHandler`
   @`0x1802EAB68`, sobrepondo o `_purecall` da base `OpenFileHandler` @`0x1802EA970`):
   1. `ArtDoc::Document::Create(path, options)` (`0x180094E10`).
   2. Extrai o nome do arquivo (`filename_v3` + `ExtraBoostFilesystem::ToUTF8String`).
   3. `ArtDoc::Document::SetTitle(document, filename)` (`0x18009C080`) — o título inicial é
      o nome do arquivo.
   4. Devolve o `unique_ptr<Document>` de saída.
   - O nome `Open` é inferido da posição na vtable e do ponto de chamada, não de símbolo
     com esse nome (confiança da evidência: `media`).

R5. **Construção do documento** — `ArtDoc::Document::Create` (`0x180094E10`) aloca `0x330`
   bytes e chama o construtor `ArtDoc::Document::Document(this, path, options, PrivateKey)`
   (`0x18008F590`):
   1. Inicializa ActionList, Errors, ChangeCollector, ContentTracker, Layers, Halftones,
      Properties, Security, DynamicObjectController, ErrorAggregator.
   2. Verifica `status(path)`; falha → log `"Document: File "` + path + `" could not be
      found"` (nível 1) e `DocumentOpenException(path, 0)`.
   3. Copia o path e entra em até **5 tentativas** de escolha de modo de abertura; logs
      observados: `"Document: Open read/write but file is write-protected: "`,
      `"Document: Open read/write: "`, `"Document: Open read-only: "`.
   4. Inicializa `ArtDoc::Security` a partir de `GADoc::GetEncryptionType` (via
      `GODocument::GetGADoc`, chamada virtual em `+0x80`) mapeado para `SetEncryption`
      com valores 1, 2, 3 (`0` = sem criptografia); consulta `GODocument::IsEncrypted` e
      `GODocument::GetPermissions`.
   5. Chama `ArtDoc::Document::Cache` (`0x180093D60`) — R6.
   6. O objeto PDF subjacente é construído por **`PDFOBJECTLAYER.DLL::GODocument::GODocument`**
      (import externo). O parse do PDF **não** está neste módulo — delegado ao PDFObjectLayer
      (inferência marcada na evidência: `0x18008F590`, confiança `media` nesse ponto).

R6. **Contagem de páginas e criação das `ArtDoc::Page`** — `ArtDoc::Document::Cache`
   (`0x180093D60`):
   1. `SwitchToWorkingFile`; obtém `PDFDocument` → `GODocument` (+0x80) e `GADoc`
      (`GADoc::GetCatalog`).
   2. Lê a contagem no campo `*(int*)(godo + 0x1A0)`; se `== -1`, chama
      `GODocument::UpdateNumPagesCache` e relê.
   3. Itera `i` de `0` enquanto `i < contagem`; por página: aloca `0x248` bytes, constrói
      `ArtDoc::Page` (`0x1800F9770`) e registra com
      `ArtDoc::ContentTracker::AddPageToDocument` (`0x180083F80`).
   4. Se o vetor de páginas continuar vazio (`[this+0x1B0, this+0x1B8)`), loga
      `"Document: File has no pages"` e lança `DocumentOpenException(path, 2)`.
   5. Lê também catálogo PDF, catálogo de separações/OutputIntent e DPart tree.
   - A lista resultante é legível por `GetPagesBegin` (`0x1800973A0`) e `GetPagesEnd`
     (`0x1800973D0`), que devolvem iterators sobre `[this+0x1B0, this+0x1B8)`.
   - Os overloads de `InsertPage` (`0x180097960` com `Part`, `0x180097AB0` com iterator)
     **não** fazem parte da abertura: inserem página em documento já aberto, mas usam o
     mesmo vetor e o mesmo `AddPageToDocument`.

R7. **Sem diálogo de importação.** Abrir um PDF vai direto ao viewport: nenhuma etapa de
   parsing é perceptível ao usuário, nenhuma opção de importação é oferecida (passo 8).

R8. **Resultado observado na abertura de `test_vector.pdf`** (passo 8–9, `shot-06`):

   | item | valor |
   |---|---|
   | Título da janela | `test_vector.pdf @ 96,45% – ArtPro+` (travessão U+2013) |
   | Overlay de caixa | `Media Box  210,00 x 297,00 mm` (vírgula decimal) |
   | Painel `Document` | `Crosshair`, `Page Boxes` |
   | Painel `Layers` | 1 camada: `Unlayered Art` (colunas `Name`, `Type`) |
   | Painel `Marks` | vazio |
   | Painel `Separations` | `ISO Coated v2 300% (ECI)`; `Cyan #1`, `Magenta #2`, `Yellow #3`, `Black #4`, `PANTONE 485 C #5` |
   | Painel `Quality Control` | `Total Area Coverage`, `Limit: 270%` |
   | Ribbon visível | `Object Browser  Colors  Images  Placed Art  Messages  Action Lists  Share & Approve  Clean  Select  Recolor  Sharper  Barcode  Screening  Trapping  Warp  3D` |

R9. **Efeito de relayout (fora de R1–R6, relevante para o clone).** Abrir o ribbon
   `Object Browser` reduziu o zoom de `96,45%` para `64,00%` sem ação de zoom do usuário
   (passo 12, `shot-07`). O viewport precisa reajustar ao abrir/fechar painéis.

## 5. Exceções

Todas as mensagens de exceção são `ArtDoc::DocumentOpenException(path, codigo)`; a
descrição textual é o nome simbólico devolvido por `0x1800A0EC0`:

```
code 0 -> "ERROR_FILE_NOT_FOUND"
code 1 -> "ERROR_FILE_ACCESS_DENIED"
code 2 -> "ERROR_FILE_INVALID"
code 3 -> "ERROR_WRONG_PASSWORD"
outro  -> "ERROR_FILE_UNKNOWN"     (inclui o 7)
```

| condição | comportamento comprovado (v240) | origem | visto na GUI? |
|---|---|---|---|
| arquivo ausente ou inacessível (`status < 2`) | log `Document: File <path> could not be found` + exceção `0` → `ERROR_FILE_NOT_FOUND` | `0x18008F590` §2, `0x1802160B0` §1 | **não** |
| MIME sem handler registrado | exceção `7` → cai no ramo padrão, `ERROR_FILE_UNKNOWN` (não há ramo 4..7) | `0x1802160B0` §4, `0x1800A0EC0` | **não** |
| documento sem nenhuma página | log `Document: File has no pages` + exceção `2` → `ERROR_FILE_INVALID` | `0x180093D60` §5 | **não** |
| PDF criptografado / senha | leitura de `GetEncryptionType`/`IsEncrypted`/`GetPermissions` → `Security::SetEncryption` 1/2/3; o código `3` (`ERROR_WRONG_PASSWORD`) existe no mapa, mas o disparo não foi observado | `0x18008F590` §4 | **não** |
| documento sem camadas | não observado. A captura mostra 1 camada sintética `Unlayered Art`; nada indica alerta por ausência de camadas | `CAP-20261121-01` §9 | não exercitado |
| PDF corrompido / offset de falha | não observado; **nenhuma** mensagem de erro apareceu em todo o fluxo de captura | `CAP-20261121-01` "Erros e limites" | não exercitado |

> A promessa antiga desta spec — "erro de parsing com detalhes do offset de falha" — **não
> tem evidência**: nem no binário (o módulo delega o parse e não expõe offset) nem na
> captura (nenhum erro foi exibido). Fica retirada como regra e registrada em §8.

## 6. Saída

- **Efeito no documento:** o `ArtDoc::Document` é criado, o título recebe o nome do arquivo
  (`SetTitle`, `0x18009C080`) + zoom corrente, as páginas do `GODocument` viram
  `ArtDoc::Page` registradas no `ContentTracker`, e o documento é devolvido ao viewport
  (R4–R6, R8).
- **O que é gravado no PDF:** **nada**. A abertura é somente leitura; nenhum `Save`/`Save As`
  foi acionado e o `sha256` do input após a sessão é idêntico ao pré-abertura
  (`ADFD91B4E95BCE3708DB37055885C355880068EE53A1472AB1DC82E0820640D7`, 1868 bytes).
- **O que é só visual:** título com zoom, overlay da Media Box, painéis
  Document/Layers/Marks/Separations/Quality Control, ribbon e o relayout de zoom (R9).
- **Sem efeito colateral em disco:** nenhum diálogo de gravação apareceu no encerramento
  (passo 13).

## 8. Em aberto

1. **Atalho de teclado de `Open...`** — `Ctrl+O` não foi exercitado em `CAP-20261121-01` e
   não foi localizado como acelerador no binário. Pergunta objetiva: qual acelerador a v240
   associa a `Open...` (tabela de ações/resources de UI) e ele abre o mesmo diálogo nativo?
2. **Contagem de páginas do documento aberto** — **não medida** na captura: `File > Pages`
   só oferece `Insert Blank Page...` / `Delete Pages...`; `Window` só lista
   `Synchronize Views`, `My Workspace Activity`, `Arrange`, `test_vector.pdf`; o
   `Object Browser` lista objetos (`4× <Path>`, `1× <Text Box>`), não páginas. O binário
   prova *como* a contagem é obtida (R6), não *qual* valor foi exibido. Pergunta: existe
   painel/indicador que exponha o número de páginas ao usuário?
3. **Registro do handler de PDF** — a string `"application/pdf"` (`0x1802EAAE8`) só tem
   xref de dados e nenhuma chamada a `RegisterFileHandler` com essa chave foi observada no
   `Document.dll`. Pergunta: qual módulo chama `RegisterFileHandler` com
   `"application/pdf"` (e com os MIMEs de `*.pdpdla`, `*.ap`, `*.art`)?
4. **Parse do PDF** — delegado a `PDFOBJECTLAYER.DLL::GODocument`; fora do módulo analisado.
   Não há nesta spec descrição de lexer/parser de PDF, tratamento de xref corrompido,
   streams comprimidos ou fontes. Cobertura disso exige evidência própria de
   `PDFObjectLayer.dll`.
5. **Mensagens de erro na GUI** — os códigos `0`, `2`, `3` e `7` existem no binário, mas
   nenhuma condição de erro foi exercitada na captura; formato do texto mostrado ao usuário
   (idioma, título da janela, botões) permanece não medido.
6. **Filtros secundários do diálogo** — apenas o filtro default
   `All supported documents (*.pdf; *.pdpdla; *.ap; *.art)` foi registrado; a lista completa
   do combo `Tipo:` não foi aberta.
7. **Função `0x180094F40`** — mapeia criptografia/permite para `GADocEncryptionParams` e é
   chamada somente por `Document::Save` (`0x18009AAF4`, `0x18009AD2A`, `0x18009B0BD`).
   Está registrada aqui apenas para separar gravação de leitura; não descreve abertura.
   Ela pertence ao escopo de **F-006 — Save**.
8. **Divergência da triagem REA** — `rea/Document.dll.md` registra hash e tamanho
   diferentes do binário do manifest (ver §7.3). Pergunta: qual arquivo foi triado, e a
   triagem deve ser refeita sobre o binário v240 correto?

Cobertura declarada e divergências do clone:

- **R2 (despacho por MIME) não está implementado.** No clone a distinção PDF × `.artplus`
  vem da ação de menu escolhida pelo usuário (`openPdf` × `openArtPlus`), não de MIME nem de
  um mapa de handlers. Consequência direta de R2: o clone não conhece
  `*.pdpdla`/`*.ap`/`*.art` e não produz o erro de "nenhum handler para o MIME".
- **R6 (contagem de páginas):** o clone conta páginas pelo parser próprio
  (`PdfDocument`/`PdfImporter`), não pelo campo `godo+0x1A0` de um `GODocument`; não há
  equivalente de `UpdateNumPagesCache`. Não há caminho "documento sem páginas" com exceção
  própria — o `PdfImporter` devolve `ok=false` com `error`.
- **Exceções:** o clone não mapeia códigos `0/1/2/3/7` nem usa os nomes
  `ERROR_FILE_*`; `PdfDocument::open()` devolve `false` sem detalhar a posição da falha —
  o "offset de falha" da versão anterior desta spec não existe em nenhum dos dois lados
  (§5, §8.5).
- **R9 (relayout/zoom)** não tem contraparte no clone.

| regra | estado | próximo passo |
