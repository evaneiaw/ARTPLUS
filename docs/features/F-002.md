# F-002 — Mark Sets

> **Estado da evidência.** Estática e comportamento são da versão-alvo **v24.03.10017**:
> `DocumentMarks.dll` (4.841.904 bytes,
> SHA-256 `E47328BD25B01B6EB36E54D8E5AA5D799F088AFC772D4FE06ED0F14B3C0FA102`,
> projeto `DocMarks_v240`) e `CAP-20261121-03` (sessão de 2026-11-21 na GUI real).
> Os quatro IDs do layout histórico que constavam desta spec foram substituídos pelos
> equivalentes v240 medidos (ver §7.3).

## 1. Resumo

Mark Set é um **documento** de marcas pré-definidas. Na v24.03.10017 ele é gerenciado no
painel `Document > Marks`: a engrenagem `▾` traz `Load Mark Set...` e
`Save/Delete Mark Set...`; aplicar um mark set carrega o arquivo, prepara o cache de marcas
e separações da página alvo e **copia o conteúdo da primeira página do mark set** para essa
página, com ids novos e com relink de marcas dinâmicas. Não há menu `Marks` na barra de
menus.

## 2. Entrada

- **Documento de mark set:** `.pdf` ou `.artplus` carregado como `ArtDoc::Document`
  (`ReadMarkSetFile`, `0x180248D30`). Basta **uma** página: só a primeira é usada.
- **Página alvo:** página do documento de destino, preparada por
  `PrepareMarksCachePage` (`0x180248720`); sem ela, a aplicação não escreve nada.
- **Flags de operação:** apagar as marcas existentes antes de copiar (bool `param_3`) e
  conjuntos de nomes/IDs de objetos repassados à cópia (`std::set<std::string>` e
  `std::set<unsigned __int64>` em `CopyMarksToPage`).
- **Pré-condições comprovadas (v240):**
  1. O arquivo do mark set precisa existir e ser regular: `boost::filesystem::detail::
     status(path)` retorna `>= 2`, senão `MarkSetFileDoesNotExist` (`0x180248D30` §1).
  2. O documento de mark set precisa conter ao menos uma página: `ApplyMarksFromSet`
     devolve `false` quando o vetor de mark sets está vazio (`0x180243EC0`), e a cópia não
     acontece quando o mapa de objetos da primeira página está vazio (`0x1800426F0` §2).
  3. O documento de destino não pode estar com o info flag `2` (`Document::GetInfoFlag`),
     caso em que `CopyMarksToPage` **não** abre `ActionGroupCreator` (`0x1800426F0` §4).
- **Pré-condições não comprovadas:** exigência de modo de edição/licença — a captura
  registra que o menu da engrenagem e o diálogo abriram **sem** aviso de licença
  (`CAP-20261121-03`, "Indício de dependência de edição/licença").

## 4. Regras

R1. **Carregar o mark set** — `DocumentMarks::TaskMarkSets::ReadMarkSetFile`
   (`0x180248D30`, 1226 bytes, `unique_ptr<ArtDoc::Document> ReadMarkSetFile(path const&,
   bool* erro)`):
   1. Zera a flag de erro e chama `boost::filesystem::detail::status(path, ec)`.
   2. `status < 2` (inexistente/não regular): emite no reporter `*(this+0x1F8)` o id
      `NDLTaskMessages.DocumentMarks.MarkSetFileDoesNotExist` (severidade 2) com o caminho
      exibido (`filename_v3` + `ToFileURI` + `GetDisplayPath`) e o texto
      `Markset file '%s' does not exist!\n`; devolve documento vazio.
   3. Arquivo válido: monta `ReadOptions`, chama `Document::Create` +
      `ForceDocumentLoad` (`0x180115E90`) e valida o resultado. Falha de leitura/parse →
      id `NDLTaskMessages.DocumentMarks.MarkSetFileError` + texto
      `Markset file '%s' error!\n`.
   4. `ContainsInputFileMark` (`0x180115040`): mark set que contém marca de arquivo de
      entrada → id `NDLTaskMessages.DocumentMarks.MarkSetContainsInputFileMark`.
   - **Não há verificação de versão nesta função.** `kVersionTooOld`/`kVersionTooNew`
     existem como string no binário, mas **não** são referenciadas aqui (a spec anterior
     afirmava "valida versão ≥ 2.0" — afirmação retirada).

R2. **Preparar o cache da página alvo** — `PrepareMarksCachePage` (`0x180248720`,
   1547 bytes; 7 parâmetros; devolve `std::vector<ArtDoc::Separation::Entry>`):
   1. Se o último bool for verdadeiro: `DeleteMarks(page)`, `DeleteExpandedMarks(page)` e
      `RemoveUnusedSeparationsFromPage(page)`.
   2. Se o bool da pilha for verdadeiro: `MoveExpandedMarks(page, false)`.
   3. `DynamicMarksController::EnableUpdates(doc, false)`.
   4. Separações: parte de `Document::GetSeparationInfo`, acumula três vetores de
      documentos via `FUN_180246B40`, aplica `Separation::FindOrAdd` para cada entrada de
      `this+0x10..0x18` e grava com `Document::SetSeparationInfo`.
   5. Para cada documento dos vetores recebidos, copia a primeira página para a alvo com
      `CopyMarksToPageWithLog(this, *GetPagesBegin(doc), page, false)`.
   - Chamada por `PrepareMarksCache(Document&)` (`0x180246C70`) e
     `PrepareMarksCache(SheetIteratorProxy&)` (`0x1802475E0`).

R3. **Aplicar o mark set a uma página** — `TaskMarkSets::ApplyMarksFromSet`
   (`0x180243EC0`, 109 bytes, `bool ApplyMarksFromSet(vector<unique_ptr<Document>>&,
   Page&, bool)`):
   1. Vetor de mark sets vazio → devolve `false` (nada é copiado).
   2. Para **cada** documento do vetor: `*Document::GetPagesBegin(doc)` (a **primeira**
      página) e `CopyMarksToPageWithLog(this, primeiraPagina, paginaAlvo, param_3)`.
   3. Devolve `true`. `param_3` = apagar as marcas existentes da página alvo antes de
      copiar. Único chamador: `ApplyExtraMarkSet` (`0x180243EA0`).

R4. **Cópia com log de diagnóstico** — `CopyMarksToPageWithLog` (`0x180245380`,
   2041 bytes):
   1. Cria dois `std::set<std::string>` vazios (nomes usados/ausentes).
   2. Chama `CopyMarksToPage(param_1, param_2, param_3, setA, setB, NULL, true)`.
   3. Se o retorno for `false` **e** o primeiro conjunto não estiver vazio, emite no
      reporter `*(this+0x1F8)`:
      - `WARNING: Missing Named Objects: %s.\nReferenced from Mark Set: %s.\nDynamic Marks
        linked to a missing object were removed from page %lu.\n`, id
        `DocumentMarks.Warning.MissingNamedObject`, severidade 1;
      - `WARNING: Missing Page Box: %s.\nReferenced from Mark Set: %s.\nDynamic Marks
        linked to a missing page box were relinked to available page box on page %lu.\n`,
        id `DocumentMarks.Warning.MissingPageBox`.
      O `%s` do mark set vem de `GetFilePath` + `stem_v3` + `ToUTF8String`; o número da
      página vem de `Page::GetPageIndex`.
   - É o **único** ponto do fluxo que produz texto de log observável na UI.

R5. **Núcleo da cópia página → página** — `DocumentMarks::CopyMarksToPage` (`0x1800426F0`,
   1102 bytes, 7 parâmetros):
   1. `FUN_180044310(GetContent(origem))` prepara o coletor; `FUN_180044820` monta o mapa
      `<idOrigem, idCopia>` e devolve a contagem.
   2. Mapa vazio → **nada é copiado** (retorno falso).
   3. Se o documento de destino **não** tem `Document::GetInfoFlag(doc, 2)`, abre
      `ActionGroupCreator`.
   4. Localiza o módulo por `FindModule(0x4D61726B)` (`'Mark'`), faz `__RTDynamicCast`
      para `MarksModule` e lê `MarksModule::GetFeatures`; o **bit 11** da máscara é usado
      como "suporta remoção/limpeza".
   5. Se `param_3` (apagar) é verdadeiro e a feature **não** está setada, chama
      `FUN_180042C00(param_1, param_2)` (limpeza prévia).
   6. `FUN_18003DF00` executa a cópia sobre o conteúdo da página de destino e o visitor é
      aplicado por `PageContent::Accept(GetContent(destino), &visitor)`.
   7. Para cada par do mapa resolve objeto antigo/novo por `Content::GetObjectWithID` e
      registra `CloneStrategy::AddClone(strategy, origem, copia)`; a sequência termina em
      `AddClone`, `RelinkDynamicObjects`, `InksChanged` e `~CloneStrategy`.
   8. `param_4`/`param_5` (conjuntos de nomes) e `param_6` (conjunto de IDs) são repassados
      ao coletor.
   - Nenhuma string literal no corpo: todo diagnóstico vem de R4.

R6. **Entradas de aplicação em documento/página** — `DocumentMarks::ApplyMarkSet`
   (`0x1800147F0`, 519 bytes) aplica a **todas** as páginas do documento alvo e
   `DocumentMarks::ApplyMarkSetToPage` (`0x180014A00`, 450 bytes) a **uma** página:
   1. Carregam o mark set por `FUN_180014C80(path*)`.
   2. Falha de carga **e** flag de apagar → `DeleteMarks` nas páginas alvo (no
      `ApplyMarkSet`) ou na página alvo (no `ApplyMarkSetToPage`); **sem** mensagem de erro
      própria nesta função.
   3. Carga ok → `ActionGroupCreator`, toca o change tracker, obtém a primeira página do
      mark set, apaga as marcas se a flag estiver ligada e chama
      `CopyMarksToPage(primeiraPagina, paginaAlvo, true, NULL, NULL, param_4, true)`.
   4. Diferença entre as duas: `ApplyMarkSet` itera as páginas e chama
      `DynamicMarksController::EnableUpdates`; `ApplyMarkSetToPage` não faz nem um nem
      outro.

R7. **Relação com separações** — o resultado de R2 (`vector<Separation::Entry>`) é o
   conjunto de separações efetivamente usadas pela página, consolidado em `this+0x10` e
   gravado por `Document::SetSeparationInfo`.

## 6. Saída

- **No documento:** os objetos da **primeira página** de cada mark set são copiados para a
  página alvo **por cima** do conteúdo existente, com ids novos e remapeamento de máscaras,
  soft masks, pais e filhos (R5); as marcas dinâmicas são religadas
  (`RelinkDynamicObjects`) e as tintas invalidadas (`InksChanged`). As separações usadas
  pela página são consolidadas e gravadas (R2/R7).
- **Log:** avisos de objeto nomeado ausente e de caixa de página ausente (E4/E5) no
  reporter do `TaskMarkSets`, com ids estáveis `DocumentMarks.Warning.*`.
- **Origem intocada:** o documento de mark set é carregado do disco e não é alterado —
  `ApplyMarkSet`/`ApplyMarkSetToPage` trabalham sobre o documento de destino, e a captura
  confirma que o `sha256` do input não muda.
- **Gravado no PDF:** nada nesta funcionalidade; a persistência pertence a **F-006 (Save)**.
- **Medido na captura:** `Save/Delete Mark Set` foi aberto e cancelado — **nenhum** arquivo
  foi gravado (`output/` vazio).

## 8. Em aberto

### 8.1 Entrada de UI no clone — pendente

O clone **não tem painel `Marks`** nem qualquer ponto de entrada para Mark Set:
`MarkSetProcessor` é compilado (`CMakeLists.txt` L54-55) mas **nenhum arquivo de UI o
referencia** — não há menu, action, dock ou diálogo. A entrada de UI será decidida pelo
`arquitetura`/`implementacao` com base em `CAP-20261121-03`; **nenhum menu foi inventado**
nesta spec.

### 8.2 Lacunas abertas

1. **Critério de "mark set relevante"** — `ApplyRelevantMarkSets` (`0x180243F40`) não foi
   decompilado nesta passada. Pergunta: quais campos do documento/página decidem a
   relevância?
2. **`WrongMarkSet` / `CannotOpenMarkSetFile`** — citados pela spec anterior, **não
   localizados** nos 7 documentos desta passada. Pergunta: existem como id de mensagem no
   `DocumentMarks.dll` ou eram invenção?
3. **`kVersionTooOld` / `kVersionTooNew`** — strings existem no binário, mas não são
   referenciadas por `ReadMarkSetFile`. Pergunta: qual função (ou qual outra camada) valida
   a versão do mark set?
4. **Diálogo de `Load Mark Set...`** — o item existe no menu, mas após `Cancel` o clique não
   abriu diálogo na captura. Pergunta: o diálogo depende de estado (mark set já carregado)
   ou a captura perdeu a janela?
5. **Submenus `Create Mark from Selection ▸` / `Add Mark ▸`, e as ações `Update Marks`,
   `Delete Mark`, `Delete All Marks`** — não abertos/acionados na captura. Comportamento
   não medido.
6. **Múltiplos mark sets simultâneos** — a existência de `ApplyExtraMarkSet`
   (`0x180243EA0`) e de vetores de documentos em R2/R3 sugere suporte; a UI não foi
   exercitada com mais de um.
7. **Relink de marcas dinâmicas** — a v240 religa e emite E4/E5; o modelo do clone ainda
   não representa marcas dinâmicas, então o relink não é feito (ver §9.2).
8. **`Save/Delete Mark Set` — gravação** — só `Cancel` foi acionado; o efeito de `Save`
   (formato gravado, destino, sobrescrita) não foi medido.
