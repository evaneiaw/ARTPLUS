# ADR-003 — Mark Sets (F-002)

## Contexto
Spec F-002; funcionalidade de Mark Sets no ArtPro+ v24.03.10017. Um Mark Set é um documento (.pdf ou .artplus) contendo marcas pré-definidas que pode ser carregado e aplicado a páginas alvo via painel `Document > Marks` → engrenagem `▾` → `Load Mark Set...` / `Save/Delete Mark Set...`. A evidência estática está em `DocumentMarks.dll` (v240) e a comportamental em `CAP-20261121-03`. A spec F-002 §7.3 aposenta endereços históricos e estabelece os equivalentes v240 medidos.

## Decisão
A funcionalidade é implementada pela classe `MarkSetProcessor` em `src/prepress/markset_processor.h/.cpp`. Esta classe opera como processador stateless que recebe o documento de destino via `setTargetDocument()`, prepara a página alvo com `prepareMarksCachePage()`, carrega o mark set com `loadMarkSetFile()` e aplica via `applyMarksFromSet()` ou `copyMarksToPage()`. A seleção de mark sets é **explícita** (o usuário escolhe o arquivo); a heurística de "mark set relevante" da v240 (`ApplyRelevantMarkSets`, 0x180243F40) não foi derivada da evidência e `identifyRelevantSets()` devolve vazio (TODO(F-002)).

A interface de usuário segue o caminho medido na v240:
- Painel `Document` → seção **Marks** → botão **engrenagem `▾`** (≈1899,303) abre menu com `Load Mark Set...`, `Save/Delete Mark Set...`, `Update Marks`, `Create Mark from Selection ▸`, `Add Mark ▸`, `Load Custom Variables Database...`, `Delete Mark`, `Delete All Marks`
- Botão **`+ ▾`** (≈1842,303) lista tipos de marca (Cut Mark, Bearer Bar, etc.)
- Diálogo `Save/Delete Mark Set`: tabela de mark sets locais, campo `Name:`, botões `Save`/`Cancel`/`-`
- **Não existe** menu `Marks` na barra de menus nem ribbon com rótulo `Marks`/`Mark Set`

## Mapeamento binário → ArtPlus
| Função (Ghidra v240) | Classe/método ArtPlus | Observação |
|---|---|---|
| `0x180248D30` — `ReadMarkSetFile` | `MarkSetProcessor::loadMarkSetFile()` | Carrega .pdf (PdfImporter) ou .artplus (DocumentSerializer); classifica erro em `MarkSetFileDoesNotExist`/`CannotOpenMarkSetFile`/`MarkSetFileError`/`WrongMarkSet` |
| `0x180248720` — `PrepareMarksCachePage` | `MarkSetProcessor::prepareMarksCachePage()` | Valida página alvo (id ≠ 0, geometria utilizável, pertence ao documento de destino) |
| `0x180243EC0` — `ApplyMarksFromSet` | `MarkSetProcessor::applyMarksFromSet()` | Carrega mark set, valida primeira página, chama `copyMarksToPage()` |
| `0x180245380` — `CopyMarksToPageWithLog` | (sem equivalente direto; diagnóstico embutido em `copyPageObjects`) | A v240 emite avisos `MissingNamedObject`/`MissingPageBox`; o clone não modela marcas dinâmicas, então o relink não é feito (TODO(F-002)) |
| `0x1800426F0` — `CopyMarksToPage` | `MarkSetProcessor::copyMarksToPage()` → `copyPageObjects()` (internal) | Copia objetos da primeira página do mark set para a página alvo com ids novos; remapeia clipMaskIds, softMaskId, parentId, children; insere na camada de topo; origem intacta |
| `0x180243F40` — `ApplyRelevantMarkSets` | `MarkSetProcessor::identifyRelevantSets()` | **Não implementado** — critério de relevância não derivado da evidência (F-002 §Em aberto item 2); devolve vazio |

## Contrato de interface (Implementado)
```cpp
class MarkSetProcessor {
public:
    MarkSetProcessor() = default;
    ~MarkSetProcessor() = default;

    // Contexto da operação: documento de destino (não possuído, precisa sobreviver ao processor)
    void setTargetDocument(ArtPlus::Document& targetDocument);

    // R2: valida e registra a página alvo para applyMarksFromSet()
    // false = página sem geometria utilizável ou que não pertence ao documento de destino
    bool prepareMarksCachePage(const ArtPlus::Page& page);

    // R1: carrega filePath (.pdf ou .artplus) para markSetDocument
    // O documento de destino NÃO é tocado; em falha retorna false e lastError() explica
    bool loadMarkSetFile(const std::string& filePath, ArtPlus::Document& markSetDocument);

    // R3: carrega o mark set e copia a primeira página dele para a página preparada
    // no documento definido por setTargetDocument()
    bool applyMarksFromSet(const std::string& markSetPath);

    // R3 (CopyMarksToPage): copia a primeira página de sourceDoc para targetPage
    // (targetPage precisa pertencer ao documento de destino). Ids novos; sourceDoc intacto.
    bool copyMarksToPage(const ArtPlus::Document& sourceDoc, const ArtPlus::Page& targetPage);

    // R4 (ApplyRelevantMarkSets): critério não derivado da evidência.
    // TODO(F-002): devolve vazio até haver critério comprovado.
    std::vector<std::string> identifyRelevantSets() const;

    // Último erro: identificador da spec + detalhe. Vazio quando não há erro.
    const std::string& lastError() const;

    // Objetos copiados na última operação bem-sucedida (0 em falha).
    int lastCopiedObjectCount() const;

private:
    ArtPlus::Document* m_targetDocument = nullptr;
    ArtPlus::PageId m_targetPageId = 0;
    std::string m_lastError;
    int m_lastCopiedObjectCount = 0;
};
```

## Fluxo de operações (v240 → ArtPlus)

```
[UI: Document > Marks > engrenagem ▾ > Load Mark Set...]
        │
        ▼
MarkSetProcessor processor;
processor.setTargetDocument(doc);
        │
        ├─ prepareMarksCachePage(targetPage)   // valida geometria, registra pageId
        │
        └─ applyMarksFromSet("path/to/markset.pdf")
                │
                ├─ loadMarkSetFile() → Document markSet (PdfImporter / DocumentSerializer)
                │       └─ classifica erros: MarkSetFileDoesNotExist / CannotOpenMarkSetFile /
                │          MarkSetFileError / WrongMarkSet
                │
                ├─ valida markSet.pageOrder() não vazio
                │
                └─ copyMarksToPage(markSet, targetPage)
                        │
                        ├─ sourcePage = markSet.page(markSet.pageOrder().front())  // PRIMEIRA página
                        │
                        ├─ sourceIds = pageObjectIds(sourceDoc, sourcePage)
                        │       // ordem de camadas + referências (clipMask, softMask, children)
                        │
                        └─ copyPageObjects(sourceDoc, sourceIds, targetDoc, targetPage, ...)
                                │
                                ├─ clona cada objeto (DocumentObject::clone() → id novo)
                                ├─ remapeia referências internas via remap[oldId] = newId
                                │       clipMaskIds, softMaskId, parentId, children
                                ├─ descarta referências que saem do conjunto copiado
                                │       (TODO(F-002): v240 religa via RelinkDynamicObjects)
                                ├─ targetLayer = camada de topo da página (cria "Mark Set" se necessário)
                                ├─ adiciona todos os clones ao documento + camada (transação atômica)
                                └─ setModified(true) no documento de destino
```

## Consequências
- **Arquivos criados:** `src/prepress/markset_processor.h`, `src/prepress/markset_processor.cpp`
- **Teste:** `tests/unit/test_markset_processor.cpp` (casos de identificação e preparação de cache)
- **Build:** `CMakeLists.txt` L54-55 + `add_test(NAME MarkSetProcessor)` L222
- **Dependências permitidas:**
  ```
  src/prepress/markset_processor
      ├─► src/document/document_model.h      (Document, Page, Layer, DocumentObject, ObjectId)
      ├─► src/document/document_serializer.h (load .artplus)
      ├─► src/pdf/pdf_importer.h             (PdfImporter para .pdf)
      ├─► src/pdf/pdf_document.h             (PdfDocument)
      └─► Qt 6.8.3 Core/Gui                  (QString, QFileInfo)
  ```
- **Dependências proibidas:** `src/ui/**`, `src/automation/**`, `MarksEngine` como estado
- **Risco:** Baixo — implementação baseada estritamente em evidência v240; gaps declarados como TODO(F-002)
- **Gaps declarados (não bloqueiam aprovação):**
  1. `identifyRelevantSets()` vazio — critério de relevância não derivado
  2. Marcas dinâmicas e religação não modeladas — `RelinkDynamicObjects` e avisos E4/E5 não emitidos
  3. Sem undo stack — operação apenas marca `setModified(true)`; v240 usa `ActionGroupCreator`
  4. Sem log de avisos — clone não tem reporter equivalente a `TaskMarkSets`
  5. Camada de destino: topo da página (cria `Mark Set`); v240 insere via `PageContent::Accept`
  6. Separações não consolidadas — `Document::SetSeparationInfo` não chamado
  7. **UI pendente** — painel `Marks`, engrenagem `▾`, diálogos não existem no clone (F-002 §8.1)

## Alternativas descartadas
1. **Implementação direta em `Document`** — viola responsabilidade única; lógica de mark set é transversal.
2. **`MarkSetConfig` struct + `process()` method** (ADR anterior) — não reflete o fluxo real em etapas (setTargetDocument → prepare → load → apply) necessário para UI e undo futuro.
3. **Heurística de relevância simulada** — seria especulação; `identifyRelevantSets()` devolve vazio até evidência.
