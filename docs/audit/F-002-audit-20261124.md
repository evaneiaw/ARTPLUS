## Divergências

1. `src/prepress/markset_processor.cpp:309-344` — `consolidateSeparations` coleta as separações,
   **descarta o vetor** e devolve `true` (comentário "Por enquanto assumimos que existe"); o
   chamador `prepareMarksCachePage` (`:297`) trata como sucesso. Spec R2.4/R7 exigem
   `Separation::FindOrAdd` + `Document::SetSeparationInfo`. É stub que finge funcionar — a spec
   §9.1 declara "o clone não consolida", mas o código afirma sucesso.
2. `src/prepress/markset_processor.cpp:244-249` — `relinkDynamicObjects` encontra o objeto de
   mesmo nome no destino e executa `break` sem religar ("relink seria feito aqui"); emite apenas
   o aviso. Spec R5.7 (`RelinkDynamicObjects`) não é cumprida; §9.1 declara a lacuna, mas o
   comentário interno sugere relink.
3. `src/prepress/markset_processor.cpp:463-465` — `copyMarksToPage` chama `copyPageObjects(…,
   false, …)`: a flag de apagar marcas existentes (R3.3/R5.5, `param_3`) não é exposta em nenhuma
   API pública; `applyMarkSetToDocument`/`applyMarkSetToPage` (`:522`, `:542`) recebem
   `deleteExisting` e **não o usam**. Efeito: `DeleteMarks` do original inalcançável pelo clone.
4. `src/prepress/markset_processor.cpp:474` — a aplicação só faz `setModified(true)`; não há
   `ActionGroupCreator`/undo (R5.3 e §9.1). Uma aplicação de mark set não é reversível em uma
   ação, ao contrário da v240.
5. `src/prepress/markset_processor.cpp:488-502` — `identifyRelevantSets` devolve **todos** os
   mark sets carregados (comentário `TODO: implementar match real`), enquanto a spec §9.1 diz
   "devolve vazio". O teste `tests/unit/test_markset_processor.cpp:139-147` só prova o caso
   vazio-com-nada-carregado; o comportamento atual não é especificado nem coberto.
6. `MissingPageBox` (E5) — `Reporter::warnMissingPageBox` existe (`src/prepress/markset_reporter.h:18`)
   e há slot de UI (`src/ui/document_marks_panel.cpp:287`), mas **nenhum** ponto do processor o
   chama (grep em `src/`): E5 não é emitida.
7. R1.4/E3 — o corpo de `loadMarkSetFile` (`markset_processor.cpp:346-389`) não tem equivalente a
   `ContainsInputFileMark`; a exceção E3 não existe no clone.
8. `docs/features/F-002.md` §8.1/§9 × código — a spec afirma "o clone não tem painel `Marks` nem
   qualquer ponto de entrada para Mark Set" e mapeia `identifyRelevantSets` em "L146-152"; hoje
   existe `src/ui/document_marks_panel.{h,cpp}` (engrenagem com `Load Mark Set...` ligada a
   `m_processor.applyMarksFromSet`) e as linhas mudaram. Spec desatualizada em relação ao código
   (o código avançou, não regrediu).
9. `src/prepress/markset_processor.cpp.tmp` — arquivo de 1 linha com o fonte inteiro concatenado
   (lixo de edição, não rastreado, não compilado). Não quebra o build, mas contamina `src/`.

Nenhuma dessas divergências derruba o que está comprovado: carga por caminho, validação de página
alvo, cópia da primeira página com ids novos e remap de referências internas estão implementados e
verdes em build limpo + 17 casos. O restante está declarado como lacuna — exceto 1, 3, 5 e 6, em
que o código se apresenta como completo/sucedido sem sê-lo.
