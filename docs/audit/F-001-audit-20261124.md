## Divergências

1. `src/prepress/cut_mark.h:43-45`, `src/prepress/cut_mark.cpp:271-275`, `tests/unit/test_cut_mark.cpp:149-151` —
   a spec R2 declara que o construtor v240 **não** grava `Orientation`, `Repetition` nem
   `LineTypes`, e R10 declara que essas chaves **não** são gravadas nem lidas; o código mantém os
   três campos nos defaults (`orientation = 1`, `repetition = 2`, `lineTypes{0}`), serializa-os em
   `toMetadata` e o teste **afirma** esses valores. Contrato aposentado sobrevive no código e no
   teste (herança de `ADR-001` D2/D3, já sinalizada em spec §8 item 17).
2. `src/prepress/cut_mark.h:41` + `src/prepress/cut_mark.cpp:158-188` — spec R6 (offset por
   `fx`, avaliado por `Localization::Evaluate`) × código: a string da fórmula nunca é avaliada; a
   geometria usa exclusivamente `offsetMm`.
3. `src/prepress/cut_mark.cpp:158-188` — spec R7/§6 (um `Group` por posição de
   `dm::MarkPositionVector`, conteúdo copiado do `FormPaint`) × código: 1 `GroupObject` com 8
   `PathObject` sintetizados. Lacuna declarada (`cut_mark.h:131`) e reconhecida em spec §6/§8.1.
4. `src/prepress/cut_mark.cpp:252-279` — spec R10 (chaves PDF+ `Position`, `Reference`,
   `ReferenceID`, `DocumentMarks_CutMark_ReferenceID`, `PDFPlusCutMark_Offset`, `Source`) × código:
   persistência apenas em metadado JSON do `.artplus`, sem nenhuma chave PDF+.
5. `src/prepress/cut_mark.cpp` (ausência de parser) — spec R11 descreve o leitor PDF+
   (`FUN_1801683E0`/`FUN_180172100`); não há implementação nem TODO nomeado para R11 no módulo.
6. `src/` (grep) — spec R12 descreve o caminho legado `AIDynamicMarks-CutMark`; zero ocorrências em
   `src/`. Sem TODO nomeado no módulo.
7. `docs/features/F-001.md` §3/§7 × `docs/behavior/TrimMarks.md:4` — a spec classifica
   `CAP-20261119-01` como "observação histórica" de versão anterior, mas o próprio artefato
   declara `Versão: 24.03.10017 (App v240)`. A cadeia de evidência comportamental é
   autocontraditória; além disso o artefato vive fora de `rag/evidence/F-001/behavior/`
   (só `docs/behavior/`).
8. Deferimentos sem spec registrada — `docs/decisions/ADR-001-cut-mark.md` D4 envia PDF+ para
   **F-001a** e o caminho legado para **F-001b**; `docs/features/` não contém `F-001a.md` nem
   `F-001b.md`. As lacunas 2–6 estão deferidas em ADR, não em spec/INVENTORY.

Nada disso é regressão de comportamento comprovado na v24: as partes implementadas (R1/R3/R4/R5/
R8/R9-parcial, E2/E6) têm teste verde e build limpo. O que não existe está declarado, não
simulado — exceto a divergência 1, em que o código **afirma** um contrato que a spec retirou.
